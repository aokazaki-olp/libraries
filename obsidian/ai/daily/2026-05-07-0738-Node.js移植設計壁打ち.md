# Node.js移植設計壁打ち

今日の壁打ちセッションのログ。テーマはGASライブラリ群のNode.js/TypeScript移植設計。

## HTTPライブラリ選定

- **got を選定**。理由：`.extend()` がこのコードベースのTransport Decoratorパターンと1対1対応。Retry-Afterネイティブサポート。TypeScriptファースト（v13）。
- axios落選：合成がミューテーション（元インスタンスを汚染する）
- ky落選：Node.js特化でなく機能薄め
- native fetch落選：全自前実装が必要で意味がない

## 移植対象の整理

**Node.jsに持っていく**
- LazyTemplate / LoggerFacade / deepFreeze / SlackFilters / SlackResolvers
- HttpClient / SlackClient / SalesforceApiClient / SalesforceAuth
- GBizInfoApiClient / GoogleSearchConsoleApiClient

**GASにとどまる**
- resolveSheet / loadAsObjects（SpreadsheetApp依存、移植する意味なし）

## LazyTemplate の可能性

> [!note] npm公開を検討中
> 依存ゼロ・単一ファイルという強みがある

- Liquidと思想が非常に近い。プレースホルダー `{{{expr}}}` はHandlebarsから、フィルター `|` はLiquidから
- **GAS/Node.js/Python全部で動く**のが最大の差別化
- Python版も存在（cronシェルのSlack通知用）。pip不要・ファイル1個がコアバリュー
- 他のテンプレートエンジンは依存ライブラリあり（gems/pip/npm）。LazyTemplateはファイル1個

パッケージ分割案：
- `@lazytemplate/core`
- `@lazytemplate/slack`
- `@lazytemplate/slack-client`

## クロスプラットフォーム設計課題

`round` フィルターの言語間差異が保留中。

| 言語 | `round(0.5)` | 方式 |
|---|---|---|
| JavaScript | `1` | round half away from zero |
| Python | `0` | banker's rounding (round half to even) |

**結論**：依存ゼロ（stdlib importすら避ける）を優先するなら**実装依存**で受け入れ、ドキュメントに明記。Slackの通知テンプレートで `.5` の丸め差異が問題になるケースはほぼない。

## 移植戦略

**戦略B（Vertical Slice）を採用**。

asyncの設計を最初に解決するため、SalesforceApiClientを一本、全層ポートする。

実装順序：
1. `Transport` interface 定義（型設計）
2. `LoggerFacade`（gotより先に必要）
3. `HttpCore` → got に置き換え（asyncの核心）
4. `ApiClient`（async化）
5. `SalesforceApiClient` + `SalesforceAuth`

## TypeScript方針

- `"strict": true` 必須（これなしのTSは意味が薄い）
- `any` 禁止 → `unknown` + 型ガード
- `interface`（公開API契約） vs `type`（Union・Utility Types）
- `enum` 禁止 → `as const` 採用（GAS版 `Object.freeze` の継続）
- `async/await` 統一、`.then()` チェーン禁止
- 公開関数の戻り値型は明示必須、内部は推論に任せる
- **型があってもランタイムガードは省略しない**（外部入力は型で守れない）
