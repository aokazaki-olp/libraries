# 正規化ライブラリ 設計定義書

## 1. ライブラリの責務

**matchKey を正確に生成することだけ。**

- 外部照合・重複確定・ファジーマッチは呼び出し側の責任
- このライブラリはファジーマッチの**前処理**を担う位置づけ
- matchKey が同一のレコードを SQL / Excel 等で抽出し、重複候補として扱う

```
matchKey完全一致         → 高信頼度の重複候補
matchKeyKanjiのみ一致   → 字体ゆれによる重複候補
どちらも不一致           → ファジーマッチ or 人手確認（呼び出し側）
```

---

## 2. エンティティ種別ごとの方針

| 種別 | 信頼できる外部ソース | 適用処理 |
|---|---|---|
| 個人 | なし | [1][2]のみ、構造に触らない |
| 団体 | なし | [1][2]のみ |
| 法人 | 国税庁法人番号API（別途） | [1][2][3] |

インボイス番号照合・法人番号API 連携はこのライブラリのスコープ外。

---

## 3. 処理フロー

### [1] 基礎正規化（全種別共通）

```
① NFKC 適用
   → 全角英数字・記号 → 半角 ASCII
   → ㈱ → (株) 等

② 記号統一（NFKC で残るもの）
   U+2010〜2015, U+FF0D → U+002D  （ハイフン・ダッシュ系）
   U+FF65, U+00B7, U+2027 → U+30FB （中黒系）
   U+301C → U+FF5E               （波線統一）
   U+00AD → 削除                  （ソフトハイフン）

③ 空白処理
   U+00A0, U+200B, U+FEFF 等 → U+0020
   多重空白 → 1 文字
   trim

【触らないもの】
   U+30FC（長音符）, U+3001, U+3002, 各種括弧
```

### [2] 字体正規化（全種別共通）

```
旧字体・異体字 → 通用字体
原則: 同じ字の字体ゆれのみ対象（別字は触らない）

例: 齋/齊 → 斎/斉、邊/邉 → 辺、冨 → 富、髙 → 高
```

**データソース**: IPA MJ文字図鑑（約6万字、CC BY 2.1 JP）  
**ストレージ**: `node:sqlite`（Node.js 組み込み、ゼロ依存）  
**ビルド**: `build/generate-db.js` で MJ文字図鑑 CSV → `data/character_variants.db` を生成し同梱  
**ランタイム**: 起動時に1回 SELECT → `Map<string, string>` に展開して以降は Map で O(1) ルックアップ

**スキーマ**:

```sql
CREATE TABLE character_variants (
  variant   TEXT PRIMARY KEY,  -- 旧字体・異体字
  canonical TEXT NOT NULL,     -- 通用字体
  source    TEXT DEFAULT 'MJ'
);
```

**字体正規化の原則**:

| 正規化する（字体ゆれ） | しない（別字） |
|---|---|
| 齋/齊 → 斎/斉 | 藤 ≠ 東 |
| 邊/邉 → 辺 | 田 ≠ 多 |
| 冨 → 富 | |
| 髙 → 高 | |

### [3] 法人格正規化（法人のみ）

**エイリアス方針**:

| 種別 | 採用 | 理由 |
|---|---|---|
| 括弧記号系 `(株)` `㈱` | ○ | 実務で頻出 |
| 銀行振込系 `カ)` `(カ` | ○ | 実務で頻出 |
| 片割れ括弧 `株)` `(株` | ○ | データ入力ミスで頻出 |
| 英字音訳系 `K.K.` `GK` | × | 英文コンテキストは知らない |
| 英語法人格系 `LLC` `Inc.` | × | 国内法人と断定できない |
| 単体略称 `合同` `有限` | × | 誤検知リスク |

> NFKC 適用後に処理するため、全角括弧は事前に半角化されている前提。

**エイリアス一覧（NFKC 適用後の表記）**:

| 法人格 | kind | 完全形 | 片割れ（行頭） | 片割れ（行末） | 銀行系（行頭） | 銀行系（行末） |
|---|---|---|---|---|---|---|
| 株式会社 | 301 | `(株)` | `株)` | `(株` | `カ)` | `(カ` |
| 有限会社 | 302 | `(有)` | `有)` | `(有` | `ユ)` | `(ユ` |
| 合名会社 | 303 | `(名)` | `名)` | `(名` | `メ)` | `(メ` |
| 合資会社 | 304 | `(資)` | `資)` | `(資` | `シ)` | `(シ` |
| 合同会社 | 305 | `(同)` | `同)` | `(同` | `ド)` | `(ド` |
| 医療法人 | 399 | `(医)` | `医)` | `(医` | — | — |
| 一般社団法人 | 399 | `(一社)` | `一社)` | `(一社` | — | — |
| 公益社団法人 | 399 | `(公社)` | `公社)` | `(公社` | — | — |
| 一般財団法人 | 399 | `(一財)` | `一財)` | `(一財` | — | — |
| 公益財団法人 | 399 | `(公財)` | `公財)` | `(公財` | — | — |
| 特定非営利活動法人 | 399 | `NPO法人` `(NPO)` | `NPO)` | `(NPO` | — | — |
| 学校法人 | 399 | `(学)` | `学)` | `(学` | — | — |
| 社会福祉法人 | 399 | `(福)` | `福)` | `(福` | — | — |

**マッチ優先順位**: 長いエイリアスを優先（greedy）

**英文入力が来た場合**:

```
"Cisco Systems G.K." → legalName: null, baseName: "Cisco Systems G.K."
```

### [4] matchKey 生成（2種類）

```
matchKey      : [1][3] 適用 + 大文字統一（元字体ベース）
matchKeyKanji : [1][2][3] 適用 + 大文字統一（通用字体ベース）
```

**各処理の適用場所**:

| 処理 | normalized（表示） | matchKey | matchKeyKanji |
|---|---|---|---|
| 基礎正規化 [1] | ○ | ○ | ○ |
| 字体正規化 [2] | × | × | ○ |
| 法人格正規化 [3] | ○ | ○ | ○ |
| 大文字統一 | × | ○ | ○ |
| 記号 | 残す | 残す | 残す |
| 空白 | 残す（多重→1文字済） | 残す | 残す |

**個人名の扱い**: 姓名構造に触らない。姓名分離が必要な場合は呼び出し側がフィールドを分けて渡す。

## 4. 出力オブジェクト

```typescript
interface NormalizeResult {
  raw: string;             // 入力そのまま
  normalized: string;      // 正規化後の表示名
  baseName: string;        // 法人格除去後の本体名
  legalName: string | null;       // 検出した法人格（例: "株式会社"）
  legalPosition: 'pre' | 'post' | 'both' | 'none' | null;
  kind: string | null;     // 国税庁 kind コード
  matchKey: string;        // 元字体ベース照合キー
  matchKeyKanji: string;   // 通用字体ベース照合キー
  ambiguous: boolean;      // true = 法人格の確信が持てない
}
```

### ambiguous フラグの条件と挙動

| # | 条件 | legalName | kind | legalPosition |
|---|---|---|---|---|
| ① | baseName に法人格名が含まれる | 検出値 | 検出値 | pre/post |
| ② | 前後で同じ法人格マッチ | 検出値 | 検出値 | `'both'` |
| ③ | 前後で異なる法人格マッチ | `null` | `null` | `null` |

**デフォルト挙動**: 前株優先で legalName/baseName を決定。呼び出し側は `ambiguous: true` を見て人手確認へ。

**例**:

```typescript
normalize("株式会社有限会社設立サポート")
// { legalName: "株式会社", baseName: "有限会社設立サポート", ambiguous: true }

normalize("(株)○○(有)")
// { legalName: null, kind: null, legalPosition: null, ambiguous: true }

normalize("(株)トヨタ自動車")
// { legalName: "株式会社", baseName: "トヨタ自動車", ambiguous: false }
```

## 5. スコープ外（明示）

- インボイス番号照合
- ファジーマッチ実装
- 法人番号 API 連携（別途検討）
- 重複の最終確定判断
- 姓名分離
